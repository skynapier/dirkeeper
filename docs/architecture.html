dirkeeper architecture

1. 概述

通用目录重定位工具。输入为 JSON 数组，包含 {source, destination} 绝对路径对。工具创建持久化任务目录以记录证据，支持断点恢复。

scan

目录分类子命令 dirkeeper scan。仅基于文件元数据和扩展名分类，不读取、移动或重命名任何文件内容。目录是分类的最小记录单位。不跟随符号链接；若根路径为符号链接，将被拒绝。

CLI 选项

选项 说明
PATH 目标路径，默认为 .。除非指定 -R 或 --max-depth，否则仅扫描根目录（深度0）。
-a 包含隐藏文件和目录（以 . 开头）。
--scope direct（默认）仅统计直接文件；subtree 聚合所有后代文件，可将父目录分类为集合类型。
--max-depth 输出记录的最大深度限制。在 subtree 模式下，遍历会深入以计算计数，但仅输出符合深度限制的记录。
--type 可重复或逗号分隔，支持 image, audio, video, software, other, mixed, empty, container。
--exclude 可重复，绝对路径或相对于根的路径，用于剪枝子树。
--min-ratio 有限浮点数，范围 [0.5, 1.0]，默认 0.5。
--format json（默认数组）或 jsonl（每行一条记录）。
-o 输出文件路径。

分类逻辑

  • 计数基础：基于文件数量，而非字节大小。
  • 类型判定：
    1. 使用 mime_guess 根据扩展名判定 image, audio, video（优先级最高）。
    2. 检查软件扩展名或 Unix 可执行标志，判定为 software。
    3. 未知类型归为 other，并计入分母。
  • 比例计算：最大类型计数 / 总文件数。
  • 最终分类：
    • 若最大计数唯一且比例严格大于 min_ratio，则分类为该类型。
    • 否则（包括平局情况）分类为 mixed。
    • 若文件数为 0 且包含直接子目录，分类为 container。
    • 若文件数为 0 且无子目录，分类为 empty。

输出规范

  • JSON 格式：默认输出到 stdout，为 JSON 数组，非摘要信封。
  • JSONL 格式：每完成一个目录，向 stdout 刷新一条记录。
  • 顺序：两种格式均遵循“子目录先于父目录，根目录最后”的顺序。
  • 文件输出 (-o)：
    • 扫描完成后原子性写入最终报告，非实时流式写入。
    • 现有报告文件会被排除在扫描之外。
    • 若发生致命错误，现有报告保持不变。
    • 输出文件的父目录必须存在。
    • 部分扫描结果可能会替换现有报告。
  • 流分离：stdout 仅包含结构化数据，诊断信息输出到 stderr。

记录字段

字段 说明
path 绝对规范化路径字符串。
relative_path 相对于根的路径，根目录为空字符串。
depth 深度，根目录为 0。
kind 小写字符串，如 image, mixed 等。
counts 对象，包含 image, audio, video, software, other 计数。
ratio 最大计数/总数，空目录为 0。
child_dirs 直接包含的子目录数量。
complete 布尔值。在 direct 模式下，若直接子项有本地错误则为 false；在 subtree 模式下，后代错误会传播导致父目录 complete 为 false。
issues 数组，包含 path 和 message。本地错误详情可能保留在后代记录中，即使父目录 complete 为 false。

退出码

退出码 说明
0 扫描完成且无错误，或 stdout 发生 BrokenPipe。
2 部分遍历完成（存在错误）或 clap 用法错误。不要假设退出码 2 时 stdout 总是可解析的 JSON；应先检查 stderr，然后检查 complete 和 issues 字段，保留可用的部分记录。过滤选项可能会隐藏错误记录，但退出码仍为 2。
1 致命错误，包括根路径无效、选项错误（如 min_ratio 超出范围）或输出失败。

2. 命令

命令 参数与行为
plan
  • --input: 映射 JSON 文件路径。
  • --task-dir: 新的绝对路径目录，不得位于 source/dest/cleanup 根目录内。
  • --cleanup-root: 可重复，指定清理根目录。
  • --limit: 限制检查数量。
  • --resolve-existing: 处理已存在目标。

目标父目录必须存在；目标必须不存在，除非通过 --resolve-existing 解决。
apply
  • --task-dir: 任务目录。
  • --max-items: 最大处理项数。
resume
  • 参数同 apply。
  • 重新验证实际内容。
  • 跳过已验证完成的项。
  • 重启已证明拥有的 staging。
  • 验证已发布目标后继续删除 source。
status 显示任务状态。
cleanup 仅删除已证明拥有的 staging（当 source 匹配且 target 不存在时），以及有界的空祖先目录。
remote
  • 在主机 --host 上通过 /usr/bin/ssh 运行相同子命令。
  • --remote-bin 指定远程二进制路径。
  • probe 打印 uname -m、内核版本、$HOME。

3. 任务目录

  • plan.json: 不可变，哈希校验，版本 2。
  • journal.jsonl: 追加写入，fsync，独占 flock。
  • evidence/NNNNNN.json: 每个文件的 BLAKE3 哈希及目录结构。
  • summary.json: 总计/完成/待处理/冲突/错误。
  • lock: 锁文件。

4. Staging

Staging 位于目标同级目录，命名为 <dst parent>/.dirplace-<task id>-<index:06>.staging，因为发布操作是同文件系统 rename。该前缀沿用旧名，以兼容已有任务。

5. 单项流程

  1. 快速路径：原生无替换 rename（macOS 使用 renamex_np RENAME_EXCL，Linux 使用 renameat2 RENAME_NOREPLACE），随后验证目标 manifest。
  2. 否则：
    1. 复制到 staging。
    2. 验证 BLAKE3 manifest 与 evidence 一致。
    3. 重新检查 source 未变。
    4. 原子无替换发布 staging 到 destination。
    5. 安全删除：验证 destination，重新验证 source，在第一个 unlink 前记录 journal deleting，从最深目录开始删除并重新哈希每个文件，移除 source 根目录。
    6. 记录 completed。
    7. 移除严格位于 cleanup roots 下方的空祖先目录。

Journal 阶段：copying, verified, published, deleting, completed, conflict, error。

来自 --resolve-existing 的重复/合并/版本项通过合并路径处理，按文件发布。

6. 冲突与安全

  • 严禁覆盖。
  • 拒绝符号链接、特殊文件、非 UTF-8 路径。
  • 拒绝 source/destination 重叠。
  • copied_source_changed 保留两者供手动协调。
  • Apply 重新验证整个未完成集合，不信任已编辑的 ready 状态。

7. NAS 兼容

  • 目录 fsync 返回 ENOTSUP 时容忍并警告一次（文件 fsync、哈希校验和 journal fsync 仍严格，因此掉电持久性受限）。
  • 当 RENAME_EXCL 返回 ENOTSUP 时，回退为独占创建空 destination 并 POSIX rename 到该空目录，绝不替换非空 destination。
  • mkdir 后中断可能留下空 reservation，保留供审查。
  • 创建 staging 后、记录 copying 前崩溃可能留下无法证明归属的 staging，保留供人工审查。

8. Remote SSH

  • 配置：StrictHostKeyChecking=yes, ConnectTimeout=15, ServerAlive*, -T。
  • 默认密钥认证，BatchMode=yes。
  • 使用 --keychain-service 和 --keychain-account 时强制密码认证，作为自身的 SSH_ASKPASS，通过 security find-generic-password 读取密码（绝不在命令行上）。
  • 参数单引号包裹，由远程登录 shell 非交互式执行，因此 --remote-bin 应为绝对路径。
  • plan 通过 stdin 流式传输本地输入文件作为 --input -。

配置

仅 dirkeeper remote 读取配置；本地命令（scan、plan、apply 等）不读取。

优先级（从高到低）：

  1. CLI 标志：--host / --remote-bin / --keychain-service / --keychain-account
  2. 环境变量：DIRKEEPER_REMOTE_HOST、DIRKEEPER_REMOTE_BIN、DIRKEEPER_REMOTE_KEYCHAIN_SERVICE、DIRKEEPER_REMOTE_KEYCHAIN_ACCOUNT（空值视为未设置）
  3. TOML 配置文件

每个值取自最高优先级层中设置的值。

配置文件位置（按顺序查找）：

  1. DIRKEEPER_CONFIG（若设置）
  2. $XDG_CONFIG_HOME/dirkeeper/config.toml
  3. ~/.config/dirkeeper/config.toml

文件缺失不报错；不可读、TOML 无效或包含未知键则报错。

[remote]
host = "nas"
bin = "dirkeeper"
    # 可选，两者同时设置或同时省略：
    # keychain_service = "<service>"
    # keychain_account = "<account>"

规则：

  • host 和 bin 在合并后为必填项（错误信息中指明对应的 CLI 标志、环境变量和配置键）。
  • keychain_service 和 keychain_account 必须同时设置或同时省略。

9. 清理规则

  • 仅删除严格位于给定根目录下方的空祖先目录。
  • 根目录保留。
  • 永不删除 #recycle 或无关文件。
  • Evidence 保留，非垃圾。
